# Experiment log — SIH26231 FieldTest Recorder

Every entry: question → hypothesis → implementation → result → decision. Raw outputs are in `results/`.
"Simulated" means rendered or spectral simulation with a real camera sensor model (Nikon D5100, NPL data —
a DSLR, **not a phone sensor**) and CIE illuminant spectra. Nothing here has been measured on a real phone yet.

| ID | Question | Hypothesis | Implementation | Result | Decision / change |
|---|---|---|---|---|---|
| E1 | Does a 24-patch reference card fix colour readings under field lighting? | Card correction cuts error substantially | `research/e1_calibration.py`: 10 colours × 5 lights × 300 captures, spectral sim | Median ΔE00 5.7–9.2 → 1.6–3.0 under daylight/tube/LED/bulb; sodium lamp still 6.2–6.5, ~10% misclassified | Keep card; need bad-light handling |
| E1b | Can the card detect bad light? Does flash/no-flash fix sodium light? | Card fit error flags sodium; flash subtraction restores accuracy | `research/e1b_badlight.py` | Fit error ≥4.6 (5th pct) under sodium vs ≤3.6 (95th pct) elsewhere; flash/no-flash median 1.7 ΔE00 | Threshold 4.0 bad-light gate; night mode needed |
| E2 | Is same-photo comparison better than separate photos for Rule 10(2) "identical results"? | Shared lighting cancels | `research/e2_sidebyside.py` | False "different": 18% (separate, card) → 2.2% (same photo); 6-apart pairs never merged; 4-apart pairs unresolvable (~35% merged) in all designs | Side-by-side capture layout; colour alone can't resolve <~5 ΔE00 |
| E3 | Which integrity design catches which tampering? | Hash-only is weak; anchor needed | `research/e3_integrity.py` | Hash-only 0/6, signed chain 4/6, chain + anchor 6/6 | Panchnama anchor |
| E4 | Does the full engine work on realistic photos (tilt, blur, glare, uneven light, phone processing, JPEG)? | Low error with gates | `e4_pipeline.py` + `photo_sim.py`, 900 photos, 3 difficulty levels | 0 wrong / 1,384 wells; 88–94% correct; all sodium rejected; uncorrected baseline 2.6–5.0% wrong. Debug found markers failed under blur (64% detection) | Markers 80→120 units, accept 3/4 (→~96%); blur gate relaxed; darker-half well estimate; live glare warning |
| E5 | Does the real record format + verifier catch attacks incl. insider admin? | All caught after rev-3 trust model | `record_core.py`, `test_integrity.py` | 12/12 caught; honest bundle verifies; ~12,000 records/s; float guard; JCS equivalence | Keep trust model |
| E6 | Can the engine read REAL published colour-test outcomes? | Works where outcomes are separated | `e6_nij_colours.py`: NIJ Std-0604.01 Table 1 Munsell → Lab; 800 photos, 4 reagents | Marquis 0.4% wrong, Mecke 0%, Simon's 0.7%. Cobalt thiocyanate 22.6% "wrong": cocaine = ephedrine = many others (identical Munsell 5B 5/10). Mecke morphine/codeine = MDA → 100% inconclusive | **Problem reframed**: output must be a colour group + substances known to give it, not "positive for drug X" |
| E7 | (a) How to set thresholds? (b) Can ML replace the card? Can it beat the rule? | (a) per-kit; (b) card needed; learned boundary helps | `e7_threshold_and_ml.py` on E8 features; leave-one-light-out | (a) best operating points differ per reagent. (b) ML without card: up to 5.6% wrong; learned calibration from raw patches abstains 21–74%; kNN/QDA up to 5–7% wrong; **RandomForest on card-corrected Lab: 0–0.5% wrong, 1–7% abstain** | Card stays (physics). Decision boundary learned offline from validation reactions |
| E8 | Colour-group classifier vs substance-nearest classifier | Colour group is more useful and safer | `e8_region_vs_substance.py` | Mecke correct 56→77%; Simon's wrong 1.3→0%; Marquis slightly worse (87→84%); Cobalt bad in both (chemistry can't discriminate) | Adopt colour-group output + "also consistent with" list; profile linter to flag unresolvable categories |
| E9 | Does flash/no-flash night mode survive a handheld phone? What capture settings does it need? | Per-frame marker alignment handles hand shake; needs locked linear capture | `e9_flash_handheld.py`, 90 trials under sodium | Street lamp only: 100% rejected. One flash frame (auto): 87% correct, 0% wrong, 12% rejected. **Flash/no-flash locked+linear: 100% correct, 0 wrong (median 1.5 ΔE00)**. Flash/no-flash with auto processing: 100% rejected (safe but useless) | Night mode tiered by device capability: locked linear pair → single flash frame → reject |
| E10 | Do hostile inputs crash anything? | Engine fails safe; verifier may not | `e10_fuzz.py` | Engine: 0 crashes; forged/faded cards rejected via fit error (22–27 ΔE00). **Verifier: 5 unhandled exceptions** on malformed bundles | Verifier: strict schema, size caps, fail-closed → 0 unhandled; attack suite still 12/12 |
| E11 | Can a learned boundary be frozen into a small deterministic lookup table? | Yes, with little loss | `e11_region_map.py`, leave-one-light-out | Table 86.7–97.3% correct, 0–1.0% wrong, 2.7–13.3% inconclusive; 91–99% agreement with forest; 72–549 KB; ~10 µs lookup; hashable for signing | Adopt signed CIELAB region map inside kit profile |
